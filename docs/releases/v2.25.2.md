# v2.25.2

v2.25.1 이후 변경 사항. 스토어 빌드에서 모아보기 채팅 최대 개수가 무제한이던 문제를 고쳤다.

## 1. 릴리스 노트

```
v2.25.2

- 채팅 최대 개수가 적용되지 않아 모아보기 창에 채팅이 끝없이 쌓이던 문제 수정 (값을 넣은 적 없으면 1000개, 새로 설치하면 100개)
- 설정의 채팅 최대 개수 칸이 비어 보이던 문제 수정
```

## 2. 원인

기본값 100을 `.env`의 `VITE_MAXNUMCHATS_DEFAULT`에서 읽었다. `.env`는 git에 없어서 GitHub Actions로 만드는 스토어 빌드에서는 `undefined`였다. GitHub 릴리스로 배포하기 시작한 2026-05-11(v2.18.x)부터다. 그 전에는 `.env`가 있는 로컬에서 빌드했다.

- 백그라운드의 기본값 채우기가 `undefined`를 넣어 저장소에 값이 없었고, 설정 칸이 비어 보였다.
- 모아보기 창의 상한 검사 `next.length >= undefined`가 늘 거짓이라 채팅을 버리지 않았다. 채팅 유지 저장도 2초마다 커지는 목록 전체를 JSON으로 재고, 1MB를 넘으면 10%씩 덜어 가며 다시 쟀다.
- 사용자가 칸에 직접 숫자를 넣으면 정상이었다.

로컬 시험은 모두 `.env`가 있는 빌드여서 드러나지 않았다.

## 3. 변경

- `src/reducer/setting.ts`: 기본값을 코드 상수 `DEFAULT_MAX_CHATS = 100`으로.
  - `missingMaxChats`: 최대 개수가 비어 있을 때 채울 값. 다른 설정이 이미 저장돼 있으면 그 시절 스토어 빌드 사용자라 `LEGACY_MAX_CHATS = 1000`, 아무것도 없으면 새 설치라 100. 다른 기본값은 코드에 적혀 있어 스토어 빌드에서도 정상으로 들어갔기 때문에 이것으로 구분된다.
  - `maxChatsOf`: 저장값을 쓸 수 있는 개수로. 비어 있으면 1000, 숫자가 아니거나 1보다 작으면 100.
- `src/entrypoints/background.ts`: 기본값 채우기가 최대 개수에 `missingMaxChats`를 쓴다. 직접 넣은 값은 그대로.
- `src/components/Extension/Local.tsx`: 모아보기 창이 `maxChatsOf`로 읽는다.

갑자기 100개로 잘리면 반년 동안 무제한으로 쓰던 사용자가 놀라므로, 기존 사용자는 채팅 유지 저장 한도(채널당 1MB, 약 1000개)와 맞춘 1000으로 한다. 업데이트 직후 백그라운드가 시작하면서 값을 채우고, 열린 탭에 스크립트를 다시 넣는 건 그 뒤라 모아보기 창은 처음부터 1000으로 뜬다(설정 상태가 저장소를 읽기 전 초기값 100으로 시작하므로 `maxChatsOf`의 1000은 실제로는 거의 쓰이지 않는다).
