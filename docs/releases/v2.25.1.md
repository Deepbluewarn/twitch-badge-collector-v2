# v2.25.1

v2.25.0 이후 변경 사항. 필터에 걸리는 채팅이 많을 때 방송 탭의 메모리가 계속 늘어나던 문제를 고쳤다.

## 1. 릴리스 노트

```
v2.25.1

- 필터에 걸리는 채팅이 많을 때 방송 탭의 메모리 사용량이 계속 늘어나던 문제 수정
```

## 2. 원인

설정 훅(`src/hooks/useGlobalSettingExtension.ts`)의 `storage.onChanged` 리스너가 어떤 키가 바뀌어도 `setGlobalSetting(prev => ...)`을 불렀다. 설정 키가 아니면 상태가 그대로라 React는 다시 그리지 않지만, 요청 객체는 다음 렌더까지 컴포넌트 대기열에 남긴다(React 19 `dispatchSetStateInternal`의 eager bailout도 `enqueueUpdate`를 한다). 이 컴포넌트는 설정이 바뀔 때만 다시 그려져 대기열이 비워지지 않았고, 요청마다 넘긴 함수가 변경 내용 전체를 클로저로 잡았다.

v2.24.0에서 채팅 유지를 `storage.session`에서 `storage.local`로 옮기면서, 탭마다 2초에 한 번 저장하는 채팅 유지 데이터(채팅 HTML, 이전 값과 새 값)가 모든 탭의 이 리스너로 들어오게 됐다. 방송 5개를 띄우면 탭 하나가 2초마다 5건씩 받아 쌓는다.

사용자 제보: Chrome에서 넓은 필터로 방송 5개, 10~15분 뒤 시스템 메모리 95%.

## 3. 변경

- `src/hooks/useGlobalSettingExtension.ts`: 설정 키(`SETTING_KEYS`)가 바뀌었을 때만 `setState`를 부르고, 클로저는 고른 설정 값만 잡는다. 거르는 키는 예전 `key in prev`와 같은 14개.
- 확장에서 badgecollector.dev로 가는 링크 5곳에 UTM(`utm_source=extension&utm_medium=referral&utm_content=<위치>`). 화면 변화 없음.
