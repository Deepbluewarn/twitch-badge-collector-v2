# v2.24.1

v2.24.0 이후 변경 사항. 실제 스토어 업데이트에서 모아보기 창의 채팅이 사라지던 문제를 고쳤다.

## 1. 릴리스 노트

```
v2.24.1

- 업데이트 중 모아보기 채팅이 사라질 수 있던 문제 수정
```

## 2. 원인

실제 업데이트는 옛 버전이 내려가고 새 버전이 뜨기까지 몇 초가 걸린다. 그 사이 채팅이 들어오면 옛 창이 그 채팅을 그리면서 `browser.i18n.getMessage`(채팅에 붙는 채널 표시)를 부르고, 확장이 내려간 상태라 오류가 난다. 렌더 중 오류라 React가 모아보기 창을 통째로 내리고, 새 스크립트가 도착했을 때는 넘겨받을 채팅이 없다.

v2.24.0까지의 시험은 확장을 강제로 다시 불러오는 방식이라 이 빈틈이 아주 짧아 드러나지 않았다. 별도 Chromium 프로필에 패키지를 설치하고 Chrome 업데이터로 실제 업데이트를 해서 재현했다(소켓 모드에서 뚜렷하다).

## 3. 변경

- `src/hooks/useFilteredChatBuffer.tsx`
  - 확장과 끊긴 뒤에는 `addChat`, `updateChat`을 무시한다. 창은 끊기기 직전 모습으로 멈춰 있다가 새 스크립트에 넘어간다.
  - 채널 표시(`title`)를 가져오다 실패해도 넘어간다.
- `src/content-scripts/base/lifecycle.ts`: `contextAlive` export

## 4. 확인

- **테스트:** vitest 427개 통과(끊긴 뒤 채팅을 받지 않는 테스트 추가)
- **실제 업데이트(Chrome 업데이터, 소켓 모드):**
  - 확장을 끄고 6초 기다림: 고치기 전 0.8초 만에 창이 비었고, 고친 뒤 6초 내내 100개 유지
  - 2.24.2에서 2.24.3으로(시험용 번호): 100개 그대로 넘어감
- **남는 것:** 2.24.0 이하에서 이 버전으로 올라올 때는 옛 코드에 이 약점이 있다. 채팅 유지를 켠 사용자는 저장소에서 다시 불러와 거의 남고, 끈 사용자는 빈틈이 길면 그 한 번 잃을 수 있다.
