# v2.29.0

v2.28.1 이후 변경 사항. 치지직 보관함에 이모티콘이 보이고, 프로필 창의 ID 복사 버튼을 끌 수 있다.

## 1. 릴리스 노트

```
v2.29.0

- 치지직 보관함에서 이모티콘이 보이지 않던 문제 수정
- 일반 설정에서 치지직 프로필 창의 ID 복사 버튼을 끌 수 있음
```

## 2. 변경

- **치지직 보관함 이모티콘** (`src/archive/`, `src/components/Archive.tsx`, 4e10f61): 보관함이 필터용 텍스트(이모티콘 토큰을 지운 값)를 저장해 이모티콘만 보낸 채팅은 본문이 비었다. 원본 메시지를 토큰째 저장하고 쓰인 이모티콘 주소를 함께 넣어 보관함 화면에서 이미지로 그린다. 이미 저장된 채팅은 그대로다.
- **ID 복사 버튼 끄기** (`src/content-scripts/chzzk/profile-actions.ts`, `src/components/GeneralSetting.tsx`, 71a0515): 일반 설정 채팅 묶음에 "프로필 창에 ID 복사 버튼"(치지직, 기본 켬). 끄면 새로고침 없이 바로 적용되고 열려 있는 창의 버튼도 뗀다. 설정 키 `chzzkProfileCopyId`, 번역 11개 언어.
  - 이유: 사용자 문의(11-12). 버튼 한 줄만큼 프로필 창이 길어져 채팅을 가린다.
- **익명 통계** (`src/telemetry/`, 2e00444): 주간 설정 기록에 `copyIdOff`(26번째). 사이트 `/api/ping`은 먼저 배포했다(아래).
- **선택자 OTA rev 22** (ca91766): 11-12 치지직 배포로 배지 예비 갈래의 해시가 `1nwpy`에서 `14814`로 바뀌었다. 구조 갈래는 그대로 맞아 기능은 정상이었다. OTA로 이미 나갔고 이 빌드에도 들어간다.
- **권한**: 추가 없음.

확장 밖:
- 사이트 `/api/ping` (badgecollector-site a3aa662): `copyIdOff`를 받는다. 주간 기록은 앞 25개만 있어도 받게 했다(전엔 목록 전체가 필수라, 그냥 덧붙였으면 옛 버전 기록이 모두 거부됐다).
- ovm `usage` 집계: 나중에 덧붙인 주간 항목은 `SETTING_SINCE`의 버전(`copyIdOff`는 2.29.0) 이후 기록만 분모로 센다. 현황판 "꺼 둔 기본 기능"에 "ID 복사 끔".

## 3. 확인

- **테스트:** vitest 566개 통과, 타입 검사 통과, Chrome 빌드 성공.
- **ID 복사 스위치 (치지직 시청자 1위 방송, 빌드 ca91766):** 켬이면 프로필 창 메뉴 끝에 "ID 복사", 끄면 열려 있던 창에서 바로 빠지고 새 창에도 없다. 다시 켜면 새 창에 다시 붙는다.
- **실제 업데이트(Chrome 업데이터, 스토어 v2.28.1 zip → 빌드 ca91766, `--headless`):** 소켓 켬/끔 × 채팅 유지 저장 켬/끔 네 조합. 처음엔 시청자 1,745명 방송에서 돌렸는데 두 조합이 업데이트 전 채팅 0개라, 그 둘(끔 / 켬, 켬 / 끔)은 9,111명 방송에서 다시 돌렸다. 표의 그 두 줄은 다시 돌린 결과다.

  | 소켓 / 채팅 유지 | 업데이트 직후 | 업데이트 뒤 60초 | 새로고침 | 빈틈 7초 |
  |---|---|---|---|---|
  | 끔 / 켬 | 창 하나, 70 유지, 띠 없음 | 74 → 100 | 100 그대로 | 100 유지, 다시 켠 뒤 안내 띠 |
  | 켬 / 켬 | 창 하나, 7 유지, 띠 없음 | 7 → 8 | 11 그대로 | 11 유지, 다시 켠 뒤 안내 띠 |
  | 끔 / 끔 | 창 하나, 3 유지, 띠 없음 | 17 → 21 | 비워짐(정상) | 3 유지, 다시 켠 뒤 안내 띠 |
  | 켬 / 끔 | 창 하나, 100 유지, 띠 없음 | 100(최대 개수) | 비워짐(정상) | 6 유지, 다시 켠 뒤 안내 띠 |

  - 업데이트 순간 0.2초쯤 창이 없는 지점이 한 번 잡히는 건 v2.25.3부터 있던 창 교체 순간.
  - 켬 / 끔은 업데이트 전에 이미 최대 개수(100)라 60초 뒤 증가는 안 보인다. 수집이 이어지는 건 1,745명 방송 결과(0 → 1 → 2)로 확인했다.
  - 빈틈 시험에서 다시 켠 뒤 창의 채팅 수가 0으로 잡히고 안내 띠가 뜨는 건 v2.28.1 때와 같다.
