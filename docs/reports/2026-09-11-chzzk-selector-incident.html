무슨 일이 있었나

한 문장으로

확장 프로그램은 치지직 화면에서 “이 이름표가 붙은 자리에 닉네임이 있다”는 약속을 보고 채팅을 읽습니다. 치지직이 그 이름표를 _container_zw6kq_에서 _container_1mc5x_로 바꿨고, 확장은 약속된 자리에 아무것도 없다고 판단했습니다.

이름표가 바뀌는 건 치지직 잘못이 아닙니다. 이 이름은 사이트를 새로 빌드할 때마다 자동으로 생성되는 값이라서, 치지직 입장에선 그냥 평소대로 배포한 것뿐입니다. 실제로 이 이름은 o04z9 → zw6kq → 1mc5x로 최소 세 번 바뀌었고, 바뀔 때마다 확장이 멈췄습니다.

왜 “필터가 죽은” 것처럼 보였나

채팅 한 줄을 처리하는 순서는 읽기 → 필터 판정 → 보여주기입니다. 문제는 첫 단계인 ‘읽기’에서 났습니다. 닉네임을 못 찾으면 그 채팅을 통째로 버리는 코드였기 때문에, 채팅은 필터 판정에 도달조차 하지 못했습니다. 사용자 눈에는 필터가 고장 난 것처럼 보이지만 필터는 애초에 호출되지 않았던 겁니다.

확인한 사실

추측을 남기지 않으려고 실제 방송 페이지를 브라우저로 열어 측정했습니다. 채팅 노드 하나하나를 세었고, 제보에 나온 그 채널(둥그레)을 포함해 여러 채널에서 같은 결과가 나왔습니다.

감시 봇은 잡았는데 왜 아무 일도 안 일어났나

자동 수정 로직이 “후보가 여럿이면 헷갈리니 포기”하도록 되어 있었습니다. 그런데 하필 이번에 바뀐 이름의 앞부분(_container_)은 화면 곳곳에 쓰이는 아주 흔한 단어라, 후보가 항상 여러 개입니다. 즉 이 로직은 가장 자주 깨지는 자리에서 항상 실패하도록 만들어져 있었습니다. 남은 건 디스코드 알림 하나뿐이었고, 그건 묻혔습니다.

selector 교체 — 이름표 대신 구조를 붙잡기

바뀐 이름으로 갈아끼우면 지금은 고쳐지지만 다음 빌드에 또 죽습니다. 그래서 빌드마다 바뀌는 해시를 아예 쓰지 않는 형태로 바꾸고, 성격이 다른 두 개의 기준을 콤마로 나란히 걸어 한쪽이 죽어도 다른 쪽이 받치게 했습니다.

aria-haspopup은 “클릭하면 프로필 창이 뜬다”는 기능에서 나오는 속성이라 디자인을 새로 빌드해도 따라 바뀌지 않습니다. _nickname_은 이름표에서 해시만 뺀 부분이라 역시 롤링에 면역입니다. 성격이 다른 두 축이라 함께 죽을 이유가 없습니다.

실제 검증에서 놓칠 뻔한 것도 있었습니다. 도네이션 채팅은 일반 채팅과 구조가 달라서 (버튼 이름이 다르고, 닉네임을 감싸는 껍데기가 하나 없음) 처음 세웠던 후보로는 도네이션 닉네임이 안 잡혔습니다. 실제 도네이션 샘플을 6건 잡아 검증하고 나서야 두 경우 모두 통과하는 형태를 골랐습니다.

5개 계층으로 보강

L1

해시 의존 제거

코드 배포 불필요즉시 복구

빌드마다 바뀌는 이름 대신 기능·구조 기준으로 교체. 라이브 3개 채널에서 필수 항목이 모두 채팅당 정확히 1건씩 잡히는 것을 확인했습니다.

L2

두 갈래로 이중화

코드 변경 0줄

콤마로 두 후보를 나란히 걸면 브라우저가 알아서 둘 다 시도합니다. 한쪽이 죽어도 기능은 유지됩니다.

단, 이러면 절반 죽어도 조용해진다는 부작용이 생깁니다. 그래서 감시 봇과 진단 도구가 갈래별로 따로 세도록 만들었습니다 — 한쪽이 죽는 순간 알림이 갑니다.

L3

전량 폐기 대신 부분 수집

100% 손실 → 부분 손실

닉네임을 못 읽어도 채팅을 버리지 않고, “이 항목은 값을 모른다”고 표시해서 넘깁니다. 배지·키워드 필터는 그대로 동작합니다.

여기에 함정이 하나 있었습니다. 모르는 값을 그냥 “빈 값”으로 두면, 제외 조건이 그걸 뒤집어 참이 되어 “이 사람 제외” 필터가 전원 매칭으로 변합니다. 그래서 값을 모르는 항목을 쓰는 조건은 아예 평가에서 빼도록 했고, 이 함정을 그대로 재현하는 테스트를 남겼습니다.

L4

감시 봇이 실제로 조치하게

이번 사고의 진짜 미스
  • 후보를 실제 방송 페이지에서 직접 돌려보고 채점 — “채팅당 정확히 1건”처럼 원래 하던 일을 그대로 하는지로 오답을 걸러냅니다. 이번 건은 정답 하나만 통과합니다.
  • 자동 수정 시 구버전용 파일까지 같이 갱신 (지금까지 빠져 있어 옛 사용자는 계속 깨진 상태였습니다).
  • 자동으로 못 고치면 GitHub 이슈 생성 — 디스코드 알림만으로는 놓칩니다.
L5

사용자에게 보이게 + 자가 복구

지금까지 완전히 무성이었음

필수 항목이 하나도 안 잡히면 곧바로 최신 설정을 내려받고(평소 1시간 대기 규칙 무시), 채팅창 위에 배너를 띄워 새로고침을 안내합니다. 사용자가 “왜 안 되지”로 시간을 버리지 않게 하는 게 목적입니다.
